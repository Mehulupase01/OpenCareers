## Confirmed Findings And Fixes

An unexpected inference transport exception was persisted verbatim in an
assessment explanation. A red regression demonstrated a synthetic secret marker
in that stored explanation. Matching now records fixed reasons for unexpected
completion/catalogue failures, parks the route, and retains consumed quota.
Code-owned DomainError categories retain their bounded diagnostic messages.
The actual OpenRouter transport normalizes unexpected network/JSON exceptions,
preserves existing domain refusal/rate-limit semantics, and rejects null response
shapes. Tests use synthetic secrets and fake HTTP, never a real key or endpoint.

The letter compiler also accepted recognizable control directives as motivation.
Typed unsupported_motivation refusal now screens known control/exfiltration/command
prose. A source quote cannot launder a recognized directive into accepted text.
Ordinary exact system-design/security/instructions requirements remain usable;
directive-containing security descriptions may be conservatively refused. This
bounded content-quality screen is not a general prompt-injection detector and
does not replace schema validation or the independent final-submission engine.

Exact source quotation also previously hid first-person candidate claims such as
invented deployment totals. The shared motivation guard now checks full text
before quote masking, permits narrow neutral interest phrases, and refuses
candidate-attributed claims in this otherwise non-factual motivation slot.
Independent packet validation, persistence and both intent/dispatch boundaries
enforce it. Previously saved unsafe LLM packets are invalidated on read, reuse or
artifact access, with existing intents invalidated. Unattempted work returns to
NEEDS_INPUT; uncertain/dispatched/confirmed states are not rewritten or replayed.
Retained-artifact regressions reconstruct the old valid report around genuinely
rendered synthetic content; they do not weaken today's validator. Content digest
checks independently refuse changed packet content at intent and dispatch.
P16-05/G5 remain reopened until the corrected build has final verification.

## Executed Boundaries

- Job/model: real public-feed normalization and ingestion, candidate/profile/policy
  persistence, MatchingRunner and inference accounting. Hostile vacancy commands
  remain in the data message; identity, work-authorization facts and a synthetic
  key are absent from it. Unknown model authority fields, private/invented fact
  IDs, mismatched spans and unsupported met requirements fail closed. Accepted
  assessments still cannot generate final authority or change owner policy.
- Final action: an actual leased submission task is fenced by owner pause. A
  fresh task after explicit resume still cannot bypass READY/packet/preparation
  requirements. No intent, attempt or receipt is created in these hostile cases.
  This is not an adverse-input READY-to-live-dispatch test or a genuine receipt.
- Transport: actual OpenRouterTransport with fake HTTP revalidates the pinned
  free route, keeps credentials in the fixed-origin authorization header rather
  than prompt data, and sanitizes network/malformed/null JSON failures.
- Imported URLs: real readPublic refuses loopback, private/link-local destinations,
  file URLs, deceptive hosts, credentials, insecure transport, unexpected ports
  and unsupported source paths/query parameters before permitted-source transport.
  This set does not independently exercise hostile DNS rebinding or socket egress.
- Documents: actual isolated imports keep commands review-required. Forged source
  locators/quotes cannot approve facts. DOCX traversal, entities, active embeddings
  and size/expansion/text limits refuse registration/publication. File/script links
  are not promoted. PDF JavaScript/action and annotated-resource fixtures retain
  readable text without executing actions or contacting a loopback tripwire.
- Mail: fake Gmail HTTP feeds real parsing, read-only service, lease/checkpoint,
  correlation and ingestion paths. Embedded instructions, false verification,
  sender/recipient/reference/attempt ambiguity, provider-ID mismatch and resource
  limits cannot create receipt/outcome/submission/owner-approval authority.
  Context acquisition is fixture-supplied here; existing P11 context tests remain
  separate evidence. No Gmail consent or real mailbox call is part of this run.

The document/mail suite uses temporary SQLite only. The job/model/authority suite
has PostgreSQL equivalents retained for CI. These fixtures do not establish an
OS sandbox, exhaustive semantic entailment, every portal variant or live provider
behavior. Existing truth validators, domain/owner/lease guards, public-address
checks, privacy/pricing tests and restore/crash evidence remain necessary.
